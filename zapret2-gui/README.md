# zapret2-gui

Графическая оболочка (Python + PySide6) для **nfqws2** из проекта [zapret2](https://github.com/bol-van/zapret2).
Ориентирована на новичков, но даёт инструменты уровня профессионала: конструктор мультистратегий, проверку синтаксиса и три сканера для поиска рабочих стратегий.

> **Принцип проекта: никаких готовых пресетов.** Приложение не содержит «волшебных» конфигов. Вы сами собираете профили, а сканеры помогают найти параметры. Так вы понимаете, что именно делает ваш обход, и можете чинить его, когда он перестаёт работать.

**Важное предупреждение.** Автор приложения не мог запустить реальный `nfqws2` в среде разработки. Логика генерации командной строки покрыта юнит-тестами и сверена с документацией zapret2, но поведение на живой сети нужно проверить вами. Список ручных проверок — в конце этого файла.

## 1. Что такое zapret2 и DPI

### 1.1. Интернет как почта

Когда вы открываете сайт, ваш компьютер отправляет **пакеты** — маленькие «письма» с адресом получателя и кусочком данных. Провайдер пересылает их дальше. Обычно ему всё равно, что внутри.

**DPI** (Deep Packet Inspection, «глубокая инспекция пакетов») — это оборудование, которое **читает содержимое** писем на лету. Оно ищет в них признаки того, что вы идёте на запрещённый или замедляемый ресурс. Какие признаки?

* В обычном HTTP — строка `Host: example.com` в заголовке запроса.
* В HTTPS (TLS) содержимое зашифровано, но самое первое сообщение клиента, **ClientHello**, содержит имя сайта открытым текстом (поле **SNI**).
* В QUIC (HTTP/3 поверх UDP) имя сайта лежит в первом пакете **Initial**; он шифруется ключом, который выводится из открытых данных пакета, поэтому DPI может его расшифровать.
* У VoIP-протоколов (STUN, WireGuard, голос Discord) есть узнаваемые «сигнатуры» — характерные байты в начале пакета.

Увидев признак, DPI может замедлить соединение, отбросить пакеты или отправить вам поддельный сброс (RST).

### 1.2. Как можно обмануть DPI

DPI — это быстрая машина с упрощённой логикой. Она не может так же тщательно собирать поток, как ваш браузер и сервер. Отсюда классы приёмов (**desync**, «десинхронизация»):

* **Разрезание (split).** Одно сообщение отправляется несколькими TCP-сегментами. Сервер склеит их, а примитивный DPI не увидит SNI целиком. Функции `multisplit`, `multidisorder` (куски в обратном порядке), `fakedsplit`.
* **Фейки (fake).** Перед настоящим пакетом отправляется **поддельный** — с безобидным именем сайта. DPI «запоминает» подделку и считает соединение невинным. Сервер подделку отбрасывает, потому что она специально испорчена: у неё маленький TTL (не доживёт до сервера), неверная контрольная сумма, неверный номер последовательности и т. п. Эти порчи называются **фулингом** (fooling).
* **Перекрытие (seqovl).** В поток добавляются «лишние» байты, которые сервер игнорирует, а DPI принимает за данные.
* **Манипуляции окном (wssize).** Сервер просят слать данные мелкими порциями.

Какой приём сработает — зависит от конкретного DPI конкретного провайдера. Поэтому стратегии подбирают экспериментально. Для этого и нужны сканеры в этом приложении.

### 1.3. Что такое zapret2 и nfqws2

**zapret2** — открытый набор инструментов против DPI. Главный компонент — **nfqws2**, программа, которая получает пакеты от ядра Linux, изменяет их и отправляет дальше.

Главное отличие от первой версии (nfqws): в nfqws2 «мозги» вынесены в **Lua-скрипты**. Программа на C разбирает пакеты и умеет их отправлять, а *что именно с ними делать* решает Lua-код. В комплекте идут два файла:

* `zapret-lib.lua` — библиотека хелперов;
* `zapret-antidpi.lua` — готовые стратегии: `fake`, `multisplit`, `multidisorder`, `fakedsplit`, `tcpseg`, `wssize`, `syndata` и другие.

Каждая стратегия подключается параметром `--lua-desync=имя_функции:параметр=значение:параметр2`. Один такой вызов называется **инстансом**. Инстансов в профиле может быть сколько угодно; они выполняются по очереди, и каждый видит изменения предыдущего.

### 1.4. Как трафик попадает в nfqws2: nftables и NFQUEUE

Пакеты проходят через ядро Linux. **nftables** — это система правил ядра («куда пакет направить»). Мы добавляем правило: *пакеты на порт 443 отправить в очередь номер 200*. Это и есть **NFQUEUE**. nfqws2 «слушает» очередь 200, получает пакеты, обрабатывает и возвращает ядру вердикт: пропустить как есть, пропустить изменённым, отбросить.

Приложение генерирует правила по образцу из документации zapret2:

```
table inet zapret2gui {
  chain predefrag { type filter hook output priority -401; policy accept;
                    meta mark & 0x40000000 != 0 notrack }
  chain post { type filter hook postrouting priority 101; policy accept;
               meta mark & 0x40000000 == 0 tcp dport { 80, 443 } ct original packets 1-12 queue num 200 bypass }
  chain pre  { type filter hook prerouting priority -101; policy accept;
               meta mark & 0x40000000 == 0 tcp sport { 80, 443 } ct reply packets 1-12 queue num 200 bypass }
}
```

Расшифровка:

* `meta mark & 0x40000000 == 0` — не трогать пакеты с меткой; такую метку ставит сам nfqws2 на отправляемые им пакеты. Без этого получился бы бесконечный цикл.
* `ct original packets 1-12` — перехватывать только первые 12 пакетов соединения. Нам нужны лишь начало TLS/QUIC и несколько следующих пакетов; остальной трафик (видео, скачивание) идёт мимо и не нагружает процессор.
* `queue num 200 bypass` — отправить в очередь 200. Слово `bypass` значит: если nfqws2 не запущен, пакеты **проходят дальше**, а не блокируются. Благодаря этому падение программы не отключает интернет.
* `notrack` для помеченных пакетов — чтобы фейки не портили таблицу соединений.

Приложение также временно включает `net.netfilter.nf_conntrack_tcp_be_liberal=1` (как в документации) и при остановке возвращает прежнее значение.

### 1.5. Профили и мультистратегия

В одной команде можно задать несколько **профилей**, разделённых `--new`. У каждого — свои фильтры (`--filter-tcp`, `--filter-udp`, `--filter-l7`, `--hostlist`) и свой набор инстансов. Для каждого соединения выбирается **первый подходящий** профиль. Поэтому порядок профилей важен: конкретное — выше, общее — ниже.

Дополнительные понятия:

* **`--filter-l7`** — протокол соединения: `http`, `tls`, `quic`, `stun`, `wireguard`, `discord` и т. д.
* **`--payload`** — тип *содержимого* текущего пакета: `tls_client_hello`, `http_req`, `quic_initial`, `stun`, `discord_ip_discovery`, `all`, `known`… Относится к следующим за ним `--lua-desync`, пока не встретится новый `--payload`.
* **`--in-range` / `--out-range`** — для каких пакетов (входящих/исходящих) работают следующие инстансы. Формат `mX-mY`, где `m` — счётчик: `n` номер пакета, `d` номер пакета с данными, `b` байты, `s` смещение seq. Примеры: `-d10` — первые 10 пакетов с данными; `a` — всегда; `x` — никогда. По умолчанию `--in-range=x --out-range=a`.
* **Блоб (`--blob`)** — именованный кусок двоичных данных (например, подделка TLS ClientHello). Встроенные: `fake_default_tls`, `fake_default_http`, `fake_default_quic`. Свои: `--blob=имя:0xHEX` или `--blob=имя:@файл`.
* **`--lua-init`** — Lua-код или файл, выполняемый один раз при старте.

## 2. Установка и зависимости

### 2.1. Что нужно

| Компонент | Зачем |
|---|---|
| Linux с ядром, поддерживающим nftables и NFQUEUE | перехват трафика |
| `nftables` (команда `nft`) | применение правил |
| zapret2 (в нём `nfqws2` и каталог `lua/`) | сам движок |
| Python 3.10+ | запуск GUI |
| PySide6, PyYAML, requests | интерфейс, конфиги, DoH-резолвер |
| `pkexec` (polkit) или `sudo` | повышение прав |
| `curl` с HTTP/3 (необязательно) | настоящая проба QUIC в сканере |
| `ping` (необязательно) | проверка связности в сканерах |

### 2.2. Установка системных пакетов

Debian / Ubuntu:

```bash
sudo apt update
sudo apt install python3 python3-venv python3-pip nftables policykit-1 iputils-ping curl git build-essential \
                 libnetfilter-queue-dev libmnl-dev libcap-dev zlib1g-dev libsystemd-dev liblua5.4-dev
```

Fedora:

```bash
sudo dnf install python3 python3-pip nftables polkit iputils curl git gcc make \
                 libnetfilter_queue-devel libmnl-devel libcap-devel zlib-devel systemd-devel lua-devel
```

Arch:

```bash
sudo pacman -S python python-pip nftables polkit iputils curl git base-devel libnetfilter_queue libmnl libcap lua
```

Названия dev-пакетов зависят от дистрибутива и версии. Если `make` ниже жалуется на отсутствующие заголовки — установите соответствующий пакет и повторите.

### 2.3. Установка zapret2

```bash
sudo git clone https://github.com/bol-van/zapret2 /opt/zapret2
cd /opt/zapret2
sudo make          # собирает nfqws2 (смотрите Makefile и docs/manual.md проекта)
```

После сборки бинарник `nfqws2` лежит в каталоге `nfq2/` (приложение ищет его там, в `binaries/my/` и в `PATH`). Если у вас иная раскладка, путь можно указать вручную в **Режимы обхода → Настройки**. В `/opt/zapret2/lua/` должны быть `zapret-lib.lua` и `zapret-antidpi.lua`.

Установочные скрипты zapret2 (`install_easy.sh` и т. п.) **не нужны**: GUI сам управляет правилами и процессом. Не запускайте одновременно системную службу zapret2 и это приложение — они будут бороться за трафик.

### 2.4. Установка GUI

```bash
git clone <ваш-путь>/zapret2-gui   # или распакуйте архив
cd zapret2-gui
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2.5. Запуск

Запускайте GUI **от обычного пользователя**, не от root:

```bash
python3 main.py
```

Права администратора запрашиваются только в момент, когда они нужны, через `pkexec` (или `sudo`). Перед этим приложение показывает окно подтверждения.

> Для `sudo` без графического агента запускайте приложение из терминала, чтобы можно было ввести пароль, либо задайте `SUDO_ASKPASS`. Для `pkexec` нужен работающий polkit-агент (есть в любом обычном графическом окружении).

### 2.6. Тесты

```bash
pytest -q
```

## 3. Первые шаги

### 3.1. Настройте пути

Откройте вкладку **«Режимы обхода»**, блок **«Настройки»**:

1. **Каталог zapret2** — обычно `/opt/zapret2`. Отсюда берутся Lua-файлы.
2. **Путь к nfqws2** — оставьте пустым для автопоиска либо укажите путь.
3. **Номер очереди `--qnum`** — по умолчанию 200. Меняйте, только если очередь занята другой программой. Сканеры используют отдельную очередь 210.
4. **`--debug`** — оставьте включённым, пока всё настраиваете.
5. **Перехват первых N пакетов** — 12 (значение из документации).
6. **Интерфейс** — пусто означает «все». Если вы хотите, чтобы обход действовал только на внешний интерфейс (например, `enp3s0`), впишите его имя.

Настройки сохраняются автоматически в `~/.config/zapret2-gui/state.yaml`.

### 3.2. Понимайте, что приложение изменит

* Создаст **одну** таблицу nftables `inet zapret2gui`. Ваши остальные правила не затрагиваются.
* Перед первым применением сохранит **резервную копию всего ruleset** в `~/.local/state/zapret2-gui/nft-backups/`.
* Запустит процесс `nfqws2` с сгенерированной командой.
* При остановке удалит свою таблицу и вернёт sysctl.

### 3.3. Первый тестовый запуск

Так как готовых профилей нет, соберём простейший.

1. Вкладка **«Профили и мультистратегия» → «Профили»** → **«Новый профиль»**.
2. В поле **`--filter-tcp`** введите `443`. Отметьте `--filter-l7`: **tls**.
3. Нажмите **«+ Добавить --lua-desync»**. В окне выберите функцию `multisplit`, в поле `--payload` выберите `tls_client_hello`, в `--out-range` впишите `-d10`. Нажмите «Добавить известный параметр» → `pos`, значение `1,midsld`. Подтвердите.
4. Внизу окна появится сформированная команда `nfqws2 …` — так вы всегда видите, что именно будет запущено.
5. Нажмите **«Проверить конфигурацию»**. Приложение прогонит команду через эвристический валидатор и (если ваша сборка это поддерживает) через `nfqws2 --dry-run`. Ошибки блокируют запуск.
6. Нажмите **«Применить nftables и запустить»**. Приложение покажет текст правил — прочитайте его — и спросит подтверждение. Затем запросит пароль администратора.
7. Откройте сайт, который у вас ограничен. Если не помогло — смотрите **«Журнал»** (там поток `--debug`) и пробуйте другие функции или сканеры.
8. **«Остановить и убрать правила»** возвращает всё как было.

Если интернет пропал — перейдите к [разделу 7](#7-диагностика-проблем).

## 4. Создание своего профиля

### 4.1. Хостлисты: к каким сайтам применять обход

Обход можно применять ко всему трафику, а можно только к выбранным доменам. Для второго нужен **хостлист** — текстовый файл со списком доменов.

1. Вкладка **«Хостлисты» → «Новый список»**, имя, например, `video`.
2. В правой части напишите по домену на строку:
   ```
   example.com
   cdn.example.net
   ```
   Поддомены включаются автоматически. Схему (`https://`) и путь приложение уберёт само, дубликаты удалит, всё приведёт к нижнему регистру.
3. **«Сохранить список»**. Файл будет лежать в `~/.config/zapret2-gui/lists/video.txt`.
4. В профиле выберите `--hostlist` = `video`, чтобы применять обход **только** к этим доменам, либо `--hostlist-exclude`, чтобы применять ко всем **кроме** них.

Хостлисты работают для протоколов, в которых nfqws2 может узнать имя хоста: HTTP (заголовок Host), TLS (SNI), QUIC (SNI из Initial).

### 4.2. Фильтры портов и протоколов

* `--filter-tcp=80,443` — список портов или диапазонов через запятую.
* `--filter-udp=443` или `--filter-udp=19294-19344`.
* `--filter-l7=tls,http` — протоколы (галочки в интерфейсе).

Если не заданы ни `--filter-tcp`, ни `--filter-udp`, профиль подходит для любого порта, но тогда приложение не знает, какие порты перехватывать в nftables, и **ничего не перехватит**. Для рабочих профилей всегда указывайте порты.

### 4.3. Выбор функции `fake`

`fake` отправляет подделку перед настоящим пакетом. Типичная сборка для HTTPS:

| Поле | Значение | Смысл |
|---|---|---|
| Функция | `fake` | |
| `--payload` | `tls_client_hello` | работать только с ClientHello |
| `--out-range` | `-d10` | только первые 10 пакетов с данными |
| `blob` | `fake_default_tls` | встроенная подделка TLS |
| `repeats` | `6` | отправить 6 раз |
| `tcp_md5` | *(пусто — флаг)* | фулинг: сервер подделку отбросит |
| `tls_mod` | `rnd,dupsid` | менять случайные поля / копировать session id |

Итоговый фрагмент:

```
--out-range=-d10 --payload=tls_client_hello
--lua-desync=fake:blob=fake_default_tls:repeats=6:tcp_md5:tls_mod=rnd,dupsid
```

Следом можно добавить второй инстанс (кнопка «+ Добавить»), например:

```
--lua-desync=multidisorder:pos=1,midsld
```

Порядок инстансов — порядок строк в таблице; его можно менять стрелками. Пустые поля `--payload`, `--in-range`, `--out-range` в строке означают «как у предыдущей строки» — так же работает и командная строка.

Про фулинг:

* `ip_ttl=N` / `ip6_ttl=N` — маленький TTL: пакет не доходит до сервера. Для IPv6 пишется отдельно.
* `ip_autottl=-2,3-20` — TTL вычисляется автоматически (формат `дельта,мин-макс`).
* `tcp_md5`, `tcp_seq=-10000`, `tcp_ack=-66000`, `tcp_flags_unset=ack`, `badsum` — другие способы испортить подделку так, чтобы сервер её не принял.

### 4.4. Маркеры позиции `pos`

Для `multisplit`, `multidisorder` и других нужно указать, **где резать**. Значения через запятую:

* число: `1`, `2`, `-1` (отрицательные — от конца);
* именованные маркеры: `method`, `host`, `endhost`, `sld`, `endsld`, `midsld`, `sniext`, `extlen`;
* со смещением: `method+2`, `endhost-1`.

`midsld` — середина домена второго уровня (например, между «exam» и «ple» в example.com).

### 4.5. Блобы и свой Lua

Вкладка **«Блобы и Lua»**:

* **Блоб:** имя `mytls`, значение `0x1603010200…` или `@/home/me/clienthello.bin`. Потом используйте имя в параметре `blob=mytls`. Валидатор проверит, что блоб объявлен.
* **`--lua-init`:** тип `file` + путь, либо тип `code` + строка кода, например `fake_default_tls=tls_mod(fake_default_tls,'rnd,rndsni')`. Файлы `zapret-lib.lua` и `zapret-antidpi.lua` подключаются автоматически и первыми.

Если вы пишете свои Lua-функции, валидатор находит их имена по `function имя(` и не считает неизвестными.

### 4.6. Несколько профилей

Создайте второй профиль кнопкой «Новый профиль». Чекбокс рядом с названием включает/выключает профиль. Помните: срабатывает **первый подходящий**. Валидатор предупредит, если два профиля имеют одинаковые фильтры и второй никогда не сработает.

### 4.7. Проверка синтаксиса

Кнопка **«Проверить конфигурацию»** делает два независимых шага:

1. **Эвристический валидатор** (модуль `validator.py`). Проверяет: формат списков портов и диапазонов; формат `--in-range`/`--out-range`; существование хостлистов, Lua-файлов, файлов блобов; чётность HEX-блобов; объявленность блобов; типы и границы известных параметров (`repeats`, `ip_ttl`, `pos`, `ip_autottl`, `seqovl`…); имена функций и параметров по справочнику из `zapret-antidpi.lua`; странные сочетания (например, `l7=quic` при одном только `--filter-tcp`). *Ошибки* блокируют запуск; *предупреждения* — нет, потому что справочник неполон и вы можете использовать собственный Lua.
2. **`nfqws2 --dry-run`** — если ваша сборка поддерживает такой флаг (он есть у первой версии nfqws). Приложение сообщит, если флаг неизвестен.

Валидатор эвристический: он ловит типичные опечатки, но не заменяет `--dry-run` и реальную проверку.

## 5. Работа со сканерами (UDP, Игры, Discord)

Сканеры подбирают параметры автоматически: перебирают **кандидатов** (профили), для каждого временно запускают nfqws2 на отдельной очереди, проводят пробу и записывают результат.

### 5.1. Что делает любой сканер

1. Создаёт папку сессии `~/.local/state/zapret2-gui/scans/<дата>-<тип>/`.
2. Резолвит цель (DoH Cloudflare → запасной системный резолвер).
3. Делает **бэкап nftables** в папку сессии и в общий каталог бэкапов.
4. Создаёт временную таблицу `zapret2gui`, которая перехватывает трафик **только к IP цели** на нужные порты — остальной интернет не затрагивается.
5. Для каждого кандидата: валидация → запуск nfqws2 → пауза → проба → остановка → разбор лога на фатальные ошибки.
6. Удаляет таблицу, возвращает sysctl, пишет итоговый `results.json`.

Содержимое папки сессии:

| Файл | Что внутри |
|---|---|
| `config.yaml` | параметры сканера и **список всех тестируемых стратегий** с их командными строками |
| `results.json` | статус, задержки, улики (`evidence`), заметки по каждому кандидату; лучший кандидат |
| `nfqws2_debug.log` | сырой вывод `--debug`; перед каждым кандидатом стоит строка-маркер `===== CANDIDATE … =====` |
| `nft-backup.nft` | резервная копия правил |

Статусы:

* `ok` — получен валидный ответ;
* `stable` / `reachable` — прямых доказательств нет, но пакеты проходят и ничего не сломалось;
* `baseline` / `inconclusive` — проба не может ответить на вопрос о DPI (причина в заметках);
* `fail` — таймаут, ICMP unreachable, падение nfqws2, пропавший пинг или ошибка Lua в логе;
* `invalid` — кандидат не прошёл валидатор.

Кнопка **«Применить выбранную как профиль»** переносит стратегию из таблицы в ваши профили.

### 5.2. А. Сканер UDP

**Назначение:** QUIC, STUN, WireGuard.

**Как пользоваться:**

1. Вкладка «Сканеры» → «А. UDP».
2. **Цель** — домен (например, `discord.com`) либо IP. **Порт** — например, 443. **l7** — `quic`, `stun` или `wireguard`.
3. Задайте диапазон `repeats` (по умолчанию 2…11), блобы через запятую (пусто = `fake_default_quic` и нулевой 16-байтовый блоб) и максимальное число кандидатов.
4. «Старт». Подтвердите повышение прав.
5. Дождитесь окончания. Лучшие кандидаты окажутся со статусом `ok`.
6. Выделите строку → «Применить выбранную как профиль».

**Перебор:** `--filter-udp=<порт> --filter-l7=<l7> --payload=<quic_initial|stun|wireguard_initiation> --lua-desync=fake:blob=<…>:repeats=<N>[:фулинг]`, где N, блоб и фулинг перебираются (сначала дешёвые — с малым `repeats`).

**Проба:**

* **QUIC:** при наличии `curl` с HTTP/3 выполняется `curl --http3-only` с подстановкой IP через `--resolve`. Это настоящий QUIC Initial с SNI — **единственный способ проверить SNI-блокировку**. Любой HTTP-ответ = успех; таймаут = провал. Без curl/HTTP3 используется проба *Version Negotiation* (1200 байт с «зарезервированной» версией, сервер обязан ответить). Она подтверждает лишь, что UDP-пакеты доходят, и помечается как `baseline`: nfqws2 такой пакет не считает QUIC Initial, поэтому ваш fake на нём даже не срабатывает.
* **STUN:** настоящий Binding Request, ожидается Binding Success Response с тем же transaction id. Нужен STUN-сервер как цель (порт 3478 или 19302 для Google).
* **WireGuard:** ответа от чужого узла быть не может, поэтому результат `inconclusive`; ICMP unreachable считается провалом.

Пример YAML — `examples/scan_udp.yaml` (кнопки «Загрузить/Сохранить YAML»).

### 5.3. Б. Сканер для игр (GameFilter Seeker)

**Проблема:** игры используют UDP на нестандартных портах, и DPI может их душить.

**Как пользоваться:**

1. Выберите «Б. Игры».
2. **Цель** — IP или домен игрового сервера (если известен), иначе любой хост, который вы можете проверять пингом. **Порты** — например, `27015-27030`.
3. «Старт».

**Перебор:** `--filter-udp=<порты> --payload=all --lua-desync=fake:blob=<0x…>:repeats=<N>:payload=all` с вариациями блоба и `repeats`.

**Проба.** Эхо-сервера обычно нет, поэтому оценка составная:

* до запуска и после — `ping` цели; если пинг был и пропал — `fail`;
* на выборку портов (по умолчанию 8) отправляются случайные UDP-пакеты; любой ответ — `ok`; ICMP port unreachable — `reachable` (пакет дошёл до хоста, DPI его не съел); тишина — `inconclusive`;
* лог nfqws2 просматривается на фатальные ошибки Lua.

Это значит, что без реального сервера сканер **отсеивает ломающие стратегии**, но не доказывает, что игра заработает. Финальная проверка — запуск игры.

### 5.4. В. Сканер стримов Discord

**Цель:** стабильный стрим экрана; Discord использует UDP-порты 19294–19344.

**Как пользоваться:** «В. Discord стрим», в цели — IP голосового сервера (его можно увидеть в сетевых соединениях во время звонка) или домен; порты оставьте `19294-19344`.

**Перебор:** `repeats` от 6 до 11 (стрим требует агрессивного обхода), несколько блобов (нулевые 16 и 64 байта, случайные 32 байта с фиксированным seed — результаты воспроизводимы, `fake_default_quic`) и два **охвата**:

* `l7` — `--filter-l7=discord,stun --payload=discord_ip_discovery,stun`: только узнаваемые служебные пакеты;
* `all` — только фильтр по портам и `--payload=all` с `payload=all` в инстансе: подделки перед **любым** пакетом, в том числе видео-потоком (первые N пакетов соединения по правилу nftables).

**Проба:** ~10 секунд UDP-«потока» (20 пакетов/с, круг по всем портам диапазона), контроль, что nfqws2 жив всё время, ошибок отправки нет, пинг не пропал. Статус `stable` означает именно это и **требует ручной проверки** настоящим стримом.

### 5.5. Остановка и безопасность

«Стоп» прерывает сканирование после текущего кандидата; в любом случае таблица удаляется. Если приложение аварийно завершилось — см. раздел 7.

## 6. Режим GameFilter

### 6.1. Зачем

В winws (первая версия под Windows) был встроенный «GameFilter». В zapret2 такой функции нет, поэтому она реализована в этом приложении как **обычный профиль, который собирается автоматически**.

### 6.2. Как это работает

Некоторые DPI реагируют на «незнакомые» UDP-пакеты игр и сбрасывают поток. Помогает отправка подделки перед ними: DPI «смотрит» на безобидный нулевой пакет и теряет интерес. Приложение создаёт профиль:

```
--filter-udp=<ваши порты> --payload=all
--lua-desync=fake:blob=0x00000000000000000000000000000000:repeats=2:payload=all
```

Почему `payload=all`: функции из `zapret-antidpi.lua` по умолчанию работают только с *известными* типами пейлоада, а игровой UDP — «неизвестный». Явное `payload=all` разрешает такую обработку. Профиль ставится **первым**, поскольку выбирается первый подходящий.

### 6.3. Настройка

Вкладка «Режимы обхода»:

1. Выберите режим **UDP** или **TCP + UDP** (в режиме «TCP» GameFilter отключён).
2. Включите GameFilter.
3. Впишите порты и диапазоны: `27015-27030,3074,50000-50100`.
4. При желании измените блоб (HEX, чётное число цифр) и `repeats`.
5. Нажмите «Проверить конфигурацию», затем запускайте.

Или найдите параметры сканером «Б» и перенесите найденные значения.

### 6.4. Предостережения

* Слишком широкие диапазоны портов перехватывают лишний трафик, хотя правило `ct original packets 1-N` ограничивает нагрузку первыми пакетами каждого потока.
* Подделки перед пакетами игры добавляют немного трафика. Для игр, критичных к задержке, подбирайте минимальное `repeats`.
* GameFilter не лечит блокировки по IP; он помогает только против сигнатурного воздействия на UDP.

## 7. Диагностика проблем

### 7.1. Интернет пропал

Правило с `bypass` не должно блокировать трафик при остановленном nfqws2, но если что-то пошло не так:

1. Нажмите **«Остановить и убрать правила»**.
2. Если GUI недоступен, выполните в терминале:
   ```bash
   sudo pkill nfqws2
   sudo nft delete table inet zapret2gui
   ```
   Затем проверьте, что таблицы нет: `sudo nft list tables`.
3. Если пропало и что-то ваше (например, брандмауэр) — восстановите бэкап. Кнопка **«Восстановить nftables из бэкапа»** выполняет `flush ruleset` и загружает последнюю копию. Вручную:
   ```bash
   ls ~/.local/state/zapret2-gui/nft-backups/
   (echo "flush ruleset"; cat ~/.local/state/zapret2-gui/nft-backups/nft-ДАТА.nft) | sudo nft -f -
   ```
   Внимание: это заменит **весь** набор правил на сохранённый.
4. Верните sysctl при необходимости: `sudo sysctl net.netfilter.nf_conntrack_tcp_be_liberal=0` (проверьте прежнее значение в журнале; обычно 0).
5. Проверьте DNS и маршрут: `ping 1.1.1.1`, `ping example.com`.

### 7.2. Как читать `--debug`

Вкладка «Журнал» показывает вывод nfqws2. Для сканеров — файл `nfqws2_debug.log` в папке сессии. Что искать:

* **Стартовые строки.** Загрузка `--lua-init`, список профилей и инстансов — убедитесь, что ваши профили и функции разобраны.
* **Строки о выборе профиля** для соединения. Если пакеты проходят, но никакой профиль не выбран — не совпали фильтры порта, протокола или хостлиста.
* **Строки о вызове `desync`** с именем инстанса и типом пейлоада. Отсутствуют — пакет не попал под `--payload` или `--out-range` (вспомните, что по умолчанию `--in-range=x`).
* **Отправка пакетов** — доказательство, что фейк реально ушёл.
* **Ошибки Lua** (`lua error`, `stack traceback`, `attempt to call a nil value`) — см. ниже.

Нет вообще никакого вывода при открытии сайта → пакеты не попадают в очередь: проверьте правила (`sudo nft list table inet zapret2gui`), совпадение `--qnum` в правилах и в командной строке и наличие счётчика на правилах.

### 7.3. Типичные ошибки

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| nfqws2 сразу завершается | неверный параметр, не найден Lua-файл, очередь занята | запустите «Проверить конфигурацию»; смотрите лог; смените `--qnum` |
| `attempt to call a nil value (global 'имя')` | функции нет: опечатка или не подключён Lua-файл | проверьте имя в диалоге, подключён ли ваш `--lua-init` |
| `bad argument …`, `invalid …` в логе | неверное значение параметра | сверьтесь с `zapret-antidpi.lua` — перед каждой функцией описаны параметры |
| Unknown blob | имя блоба не объявлено | вкладка «Блобы и Lua» |
| Профиль не срабатывает | порядок профилей, фильтры | сделайте конкретный профиль выше; проверьте `--filter-*` |
| Сайт не открывается *хуже*, чем без обхода | слишком агрессивная стратегия, фулинг убивает настоящий пакет | уменьшите `repeats`, смените фулинг, попробуйте другой `pos` |
| QUIC не проверяется | у curl нет HTTP/3 | установите curl с HTTP/3 либо тестируйте браузером |
| `pkexec` не показывает окно | нет polkit-агента | запустите агент или используйте `sudo` из терминала |
| Нет эффекта на IPv6 | параметры TTL заданы только для IPv4 | добавьте `ip6_ttl`/`ip6_autottl` |

### 7.4. Правила nftables не применяются

* `nft --version` — установлен ли nftables;
* `sudo nft -f` ругается на `queue` — в ядре нет `nft_queue`/`nfnetlink_queue`: `sudo modprobe nfnetlink_queue`;
* конфликт с `iptables-nft` или firewalld — наша таблица отдельная, но может быть переопределена политикой; смотрите `sudo nft list ruleset`.

### 7.5. Совсем сломалось — общий сброс

```bash
sudo pkill nfqws2
sudo nft delete table inet zapret2gui
mv ~/.config/zapret2-gui/state.yaml ~/.config/zapret2-gui/state.yaml.old   # чистое состояние GUI
```

## 9. Что сканеры не умеют (честно)

* Нет «детектора DPI». Сканер измеряет *наблюдаемый результат* (ответ пришёл или нет), а не причину.
* Проба QUIC без curl+HTTP/3 не проверяет блокировку по SNI.
* Для игр и Discord без сервера, отвечающего на ваши пакеты, максимум — «не сломали и пакеты доходят». Окончательное решение принимается в реальном сценарии (игра, стрим).
* Результаты зависят от времени суток, нагрузки провайдера и маршрута. Повторите лучшие стратегии несколько раз.
* Список функций и параметров в `functions_db.py` составлен по документации и может отставать от вашей версии zapret2. Незнакомые функции и параметры дают предупреждения, а не ошибки.

## 10. Что проверить вручную

1. `nfqws2` стартует с командой из окна предпросмотра, запущенной вручную в терминале.
2. `nfqws2 --dry-run …` — поддерживается ли флаг в вашей сборке.
3. `sudo nft list table inet zapret2gui` после запуска — правила на месте; после остановки — таблицы нет.
4. Параметр `payload=all` внутри `fake` (GameFilter) принимается вашей версией `zapret-antidpi.lua`: найдите описание стандартных параметров в начале файла.
5. Фильтры `--filter-l7=discord` и тип `discord_ip_discovery` существуют в вашей сборке (`nfqws2 --help`, лог `--debug`).
6. Бэкап и восстановление nftables на тестовой машине.
7. Окно pkexec/sudo и отказ от ввода пароля (приложение не должно зависать).
8. Все три сканера на тестовой цели: наличие папки сессии, `config.yaml`, `results.json`, `nfqws2_debug.log`.
9. После сканера: `sudo nft list tables` не содержит `zapret2gui`; `sysctl net.netfilter.nf_conntrack_tcp_be_liberal` вернулся.

Пользуйтесь инструментом в рамках закона вашей страны и условий вашей сети.
